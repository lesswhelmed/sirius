# Build + install the Sirius Android app on a USB device

This is an **Expo + EAS Build** app (`apps/mobile`). Release/production builds run in
EAS cloud. The `android/` dir is gitignored and regenerated by `expo prebuild` — never
commit it.

## The one critical fact

**An EAS `production` build is an `.aab` (Android App Bundle). You CANNOT `adb install`
an `.aab`** — it's a Play Store publishing format. To put a production build on a device
you must convert the AAB → a **universal APK** with `bundletool`, then `adb install` that.

## Ground truth for this repo (don't re-derive)

- **EAS project:** `@minasaleeb/sirius`, id `c14faf73-b1f9-425e-b66b-974ac26b827c`
  (`apps/mobile/app.json`). **Run all `eas` commands from `apps/mobile`.**
- **Application id:** `dev.copt.sirius`.
- **eas.json `production`:** `distribution: store` (→ AAB), `autoIncrement`/`appVersionSource: remote`
  (EAS owns `versionCode` — no manual bumping), `requireCommit: true` — the git tree must
  be **clean or the build refuses to start** (untracked files count as dirty).
- **Prod server URL is wired in eas.json** `production.env.EXPO_PUBLIC_AUTH_BASE_URL` =
  `https://lesswhelmed.com`; a production build runs **standalone** (no Metro/dev server)
  and talks to the live backend. (`apps/mobile/.env` holds the dev `sirius.local` URL and
  is NOT used by cloud builds.)
- **Build profiles → artifact:** `production` → `.aab` (needs bundletool to sideload);
  `preview` → `.apk` (directly `adb install`-able, the shortcut if you don't need prod
  signing/env); `development` → dev-client `.apk` (needs Metro).

## Part 0 — Decide scope with the user first (ask, don't assume)

A cloud build consumes an EAS build (and there are billing overages on this account).
Confirm before building:

- **Fresh build vs. reuse a finished one?** Fresh picks up latest `main`; reuse is instant
  but may be stale. Check: `cd apps/mobile && bunx eas-cli build:list --platform android --limit 5 --non-interactive --json`.
- **If fresh & the tree is dirty:** `requireCommit` will block. Do **NOT** commit/stash
  files you didn't create — this repo runs a multi-agent swarm on a shared tree. Hand any
  stray untracked file back to the user and let them resolve it.

## Part 1 — Preflight deps (one-time)

```sh
brew install bundletool      # AAB → APK converter (needs a JRE: brew install openjdk)
adb devices -l               # Android platform-tools; confirms the device is seen
```

## Part 2 — Build the production AAB (if building fresh)

```sh
bun run mobile:build:android:ci     # eas build --profile production --platform android --non-interactive
```

Watch the printed build URL. It auto-increments `versionCode`, uses the remote prod
keystore, and loads the `production` env (lesswhelmed.com). If it **ERRORS**, open the
build-logs URL and fix the root cause. (Historical Android build failures + fixes are in
`apps/mobile/docs/ANDROID-BUILD.md` and memory `android-eas-build-gotchas` /
`android-fingerprint-masked-view`.)

## Part 3 — Convert + install to the device (the automatable part)

```sh
bun run mobile:install:android      # latest FINISHED prod AAB → universal APK → adb install
```

The bundled script (`scripts/install-android-prod.sh`) resolves the latest finished
production AAB, downloads it, runs `bundletool build-apks --mode=universal`, extracts
`universal.apk`, and `adb install -r`s it. Pass an explicit AAB URL or local path as the
first arg to pin a specific build. Env: `ANDROID_SERIAL=<serial>` to target one of several
devices; `NO_INSTALL=1` to just produce the APK.

Then launch: `adb shell monkey -p dev.copt.sirius -c android.intent.category.LAUNCHER 1`.

## Gotchas learned the hard way

- **Signature mismatch on reinstall.** The universal APK is debug-signed
  (`~/.android/debug.keystore`). A locally-run debug build (`expo run:android`) uses the
  same keystore, so `install -r` upgrades cleanly. But if a differently-signed build of
  `dev.copt.sirius` is present you'll get `INSTALL_FAILED_UPDATE_INCOMPATIBLE` — then
  `adb uninstall dev.copt.sirius` first, **which wipes the app's data + login**. Confirm
  with the owner before wiping.
- **Device drops off USB mid-flow.** `adb devices` goes empty if the cable switches to
  charge-only, the screen locks, or the "Allow USB debugging?" prompt is dismissed.
  Reconnect (data mode) + unlock + Allow, re-check `adb devices -l`, then retry install.
- **Debug APK ≠ standalone.** A `debug`/dev-client APK needs the Metro dev server
  (`bun --cwd apps/mobile start`, + `adb reverse tcp:8081 tcp:8081` over USB). Only
  `preview`/`production` builds run without Metro.

## What "done" means

The production build is installed and launches on the connected device. Store submission
(`eas submit`) is a separate flow — see `mobile:submit:android` / `apps/mobile/docs/ANDROID-BUILD.md`.
