## Why this matters

`three` is pinned inconsistently: `apps/mobile` uses exact `0.181.0`, while
`apps/web` and the shared `packages/embedding-scene` use `^0.182.0`. The shared
scene package (`@repo/embedding-scene`) is imported by both apps, so it compiles
and runs against **two different `three` minors** depending on which app pulls it.
Geometry/material API drift between 0.181 and 0.182 can produce mobile-only
rendering bugs that web CI never catches. Aligning both hosts on one minor removes
that class of "works on web, broken on device" bug.

## Steps

### Step 1: Decide the alignment direction (default: align mobile UP to 0.182)

Default: bump `apps/mobile` to `^0.182.0` so all three match web/package. BUT first
check the mobile constraint: search `apps/mobile` and `docs/` for any documented
`three` upper bound (`grep -rn "three" apps/mobile/docs docs | grep -iE "0.18|expo-gl|version"`).
If a hard upper bound at `0.181` is documented, invert the plan: align web +
`embedding-scene` **down** to `0.181.x` instead (and set the peer to just
`^0.181.0`). Record which direction you chose.

**Verify**: you have a single target version string decided (e.g. `^0.182.0` for
all, or `0.181.0`/`^0.181.0` for all).

### Step 2: Update the manifests to the single target version

Set `three` (and web's `@types/three`) to the chosen version in all three package
manifests. If root `overrides` includes `three`, set it there too so resolution is
forced. Then `bun install`.

**Verify**: `bun pm ls | grep -i three` (or grep `bun.lock`) shows **one** resolved
`three` version.

### Step 3: Typecheck

**Verify**: `bun run db:generate` then `bun run check-types` → exit 0. If web now
fails to typecheck against the aligned `@types/three`, that's a signal the two
minors had real API drift — report it (this is exactly the bug class we're closing,
but the fix belongs in a separate typed change, not this alignment plan).

### Step 4: Hand off the runtime visual check

This plan cannot drive the iOS simulator. In your report, explicitly request the
operator (or a follow-up) verify: (a) the mobile 3D scene renders — the Explore/Tree
"Map" and `constellation-scene.tsx`/`map-view.tsx`; (b) the web `/space` Map tab
renders. Note that a `three` minor bump is the classic cause of a blank/exploded
`@react-three/fiber` canvas, so this manual check is mandatory before merge.

**Verify**: report includes the explicit manual-verification request with the exact
surfaces to check.

## STOP conditions

Stop and report if:

- A documented mobile `three` upper bound conflicts with bumping to 0.182 AND
  aligning down to 0.181 would force web/`@types/three` code changes — the two
  hosts genuinely can't share a minor without code work; report both options.
- `bun install` can't resolve a single `three` (a transitive dep of r3f/drei pins a
  conflicting range) — report the conflict; do not force-resolve blindly.
- Typecheck fails after alignment (real API drift) — report the errors; do not
  patch scene code to make it compile as part of this plan.

## Maintenance notes
